The problem

Garbage in, garbage recalled.

Most agent memory saves everything it sees. A month later, recall serves back stale guesses, half-finished thoughts and duplicates, all with the same confidence as the facts.

The usual alternative is one huge notes file that loads into every session in full, whether today's task needs it or not.

Philosophy

A small library you actually trust.

  • You approve every memory.Agents suggest. Nothing is written, edited or deleted without you.
  • Nothing beats something wrong.If no memory is a good match, the agent gets no results instead of loosely related noise.
  • A memory is evidence, not truth.Records are dated. When they disagree with the current code, the code wins and the conflict is shown to you.
  • Your machine, your data.Records, search index and embedding model all live locally. No account, no cloud, no network calls after setup.
How it works

Capture, recall, dream.

1 · Capture

At the end of a session

The agent looks back and proposes a few small, durable facts. You keep, edit or drop each one.

agent Worth remembering: "Staging deploys need the VPN". Save?
you Yes.
2 · Recall

While the agent works

The agent searches on its own and opens only the memory it picks.

search "staging deploy hangs"
→ Staging deploys need the VPN
search "banana smoothie"
→ nothing, as it should be
3 · Dream

Once a week

The library looks back at itself and suggests what to fill in, merge or retire.

dream "billing webhook" was searched 9 times and never found. Write it down?
dream "Release steps" and "Release checklist" say the same thing. Merge?
Under the hood

Every choice is about context.

An agent's context window is its working memory. Each design decision is there to fill it with the right thing, not more things.

Memories that stand alone

No blind chunking of documents. Each memory is one idea, written to make sense on its own, with a title and the aliases people actually use.

Search, then fetch

Search returns a short shortlist with one-line previews. The full text enters context only when the agent picks a record.

Precise before fuzzy

Exact names first, then keywords, then typos, and meaning only as a last resort. Acronyms and internal jargon match exactly instead of drifting.

Lazy by default

The embedding model loads only when a search really needs meaning. Most lookups never touch it.

It measures itself

You can see what recall is doing.

Every search leaves a small trace: the search terms, what matched, and how well. No memory content is ever copied into it, and it expires after 90 days. From that you can see which searches find something, which keep coming back empty, and which memories never come up at all.

That is what dreaming runs on. Gaps become new memories and dead weight gets retired, based on how your agents actually search rather than on guesswork.

What it won't do

Deliberately boring.

  • Write memories on its own
  • Quietly correct a record that looks out of date
  • Send anything to the cloud
  • Copy your memories into its usage log
  • Pad results to look helpful
  • Grow a taxonomy nobody asked for
Works with

Any agent that speaks MCP.

Three tools: search, fetch and save. Reads run automatically and saves ask first. It comes with a skill for end-of-session capture and weekly dreaming.
